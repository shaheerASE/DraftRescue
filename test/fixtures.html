Draft Rescue test fixtures

Green = must be captured. Red = must never be captured. Phase 5 expands this page and adds the manual checklist for real sites.

Plain textarea

Expect: captured.

Plain text input

Expect: captured.

contenteditable

Expect: captured, with sanitised HTML stored alongside the plain text. This is the case the alternatives do not handle.

Input inside an OPEN shadow root

Expect: captured. Only reachable because we resolve the event target through composedPath().

Reddit-shaped composer (Lexical inside a custom element)

Expect: captured. Modern editors nest the text several elements deep inside a web component, so the event target is never the editable host. This is the shape that has to keep working.

Input inside a CLOSED shadow root

Expect: NOT captured. Known limitation — a closed root is invisible to every extension by design. Documented, not worked around.

Same-origin iframe

Expect: captured. A separate copy of the content script runs in the frame and messages the service worker itself.

Password field

Expect: NOT captured, by type.

Password field after a show/hide toggle

Expect: NOT captured, even once its type becomes "text". Type into it, then press the button, then type more.

Card number field

Expect: NOT captured, by name and by autocomplete.

Vague field inside a checkout form

Expect: NOT captured — the form gives it away.

Ordinary field containing a card number

Expect: captured, but with the card number replaced by [redacted]. The second safety layer, independent of what the field is called.

Text below the minimum length

Expect: NOT stored. Under 15 characters is not a draft.
