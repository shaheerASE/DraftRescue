## Needs a person — you cannot ship without these

### 1. Icons

`public/icon/` currently holds placeholders generated by
`scripts/make-icons.mjs`. They are geometry, not design: a rounded square with a
circular arrow. They exist so the extension looks deliberate during development.

**Get a designer.** The icon is the single most-seen thing about the extension
and a generated one reads as unfinished.

Sizes needed: 16, 32, 48, 128 px PNG. The 128 is what the store shows.

What the icon has to survive:
- 16px in the toolbar, next to other extensions
- Both light and dark browser themes
- A crowded store grid, where recognisability matters more than detail

The current mark — a circular "restore" arrow — is the right idea. It is the
execution that needs a hand.

### 2. Screenshots

Five, 1280×800 or 640×400 PNG. Captions in `store/LISTING.md`.

Take them from the real extension with real-looking content. Do not mock them
up — a screenshot that does not match what the extension does is a listing
rejection, and it is dishonest anyway.

Use content you are happy for strangers to read. Whatever is in those images is
public forever.

### 3. A hosted privacy policy URL

Chrome requires a **publicly reachable URL**. A file in the repository is not
enough for the form, even though it is the source of truth.

Cheapest options that will not rot:
- GitHub Pages on this repo — free, and the URL survives as long as the repo does
- The raw GitHub file URL — works, though it looks unfinished
- Any static host

Whatever you pick, keep `PRIVACY.md` as the canonical copy and publish from it,
so the two cannot drift apart.

### 4. A licence for the source — done

**GPL-3.0-or-later.** `LICENSE` is in the repository root and `package.json`
declares it.

It was listed here because the privacy claim depends on it: the argument is
"read the source and verify it", which only works if the source is public, and
public source without a licence is legally all-rights-reserved — nobody may copy
it even to check it. Copyleft keeps the code auditable while making a
closed-source commercial fork a violation. Reasoning in
[`../docs/1-LICENSING.md`](../docs/1-LICENSING.md).

One thing still needs you: the copyright line in `README.md` names the git
identity `shaheerDev`. Replace it with the legal name or registered entity that
should hold the copyright.

### 5. A link to the source, in the listing

Now that the extension is GPL, distributing the built package carries one
obligation: recipients must be able to get the **source that built it**.

The repository being public satisfies this, but only if people can find it. Add
the repository URL to the listing's detailed description — a single line under
the "you can check this yourself" paragraph is enough:

```
Source code: https://github.com/<you>/DraftRescue
```

This is also the single most persuasive line in the whole listing for a privacy
tool, so it earns its place twice over.

## Before you upload

```bash
npm test              # 447 unit tests
npm run build
npm run check:offline # proves the privacy claim against the built files
npm run smoke         # the whole capture path in a real browser
npm run smoke:prompt  # the restore prompt
npm run smoke:ui      # popup and settings
npm run size          # content script under its 20 KB budget
npm run zip           # the package to upload
```

Then, by hand: `test/MANUAL-CHECKLIST.md`. Do not submit on fixture results
alone. The fixtures prove the mechanism; the checklist proves the product, and
the store listing describes the product.

## What review will focus on

Be ready for these. They are the predictable ones.

**Why `<all_urls>`?** The hardest question, and the one the reviewer is really
asking. The answer is in `store/PERMISSIONS.md`: text is lost on any site, and
there is no way to know in advance which one. Do not hedge it and do not offer
to narrow it — a narrower list would make the product not work.

**"Your listing says nothing is uploaded. Prove it."** The package contains no
network API and requests no host permissions. `npm run check:offline` is the
demonstration. Offer it; do not lecture.

**Privacy practice answers.** See the table in `store/PERMISSIONS.md`, including
the note on why "Personal communications" is answered No.

**Expect a slow first review.** An extension that reads text on every site is in
the most-scrutinised category there is. Days rather than hours is normal. Do not
resubmit while one is pending — it restarts the queue.

## Version and release

`0.1.0` in `package.json` is the version; WXT copies it into the manifest.

Chrome will not accept the same version twice, and will not accept a version
lower than one already published. Bump it before every upload, even to fix a
typo in a screenshot.

---

## After it is live

- **Read every one-star review.** For this product they will mostly be "it
  didn't work on <site>", which is a bug report with a site name attached — the
  most useful thing you can get.
- **Watch for anything about data.** If a user ever believes their drafts left
  their machine, answer publicly, immediately, and point at the verification
  step. A privacy claim that goes unanswered is assumed false.
- **Keep the manual checklist current.** Sites rewrite their editors. Something
  that worked at launch will break, and it will break quietly — nobody reports a
  thing that silently stopped saving, they just uninstall.
